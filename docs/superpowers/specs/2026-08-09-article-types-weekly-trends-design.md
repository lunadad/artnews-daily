# 기사 유형 분류와 주간 미술계 동향 설계

작성일: 2026-08-09

## 1. 목표와 범위

Artnews의 국제 Top 5와 국내 브리핑 기사에 결정론적인 기사 유형을 저장하고, 최근 최대 7일의 데이터를 바탕으로 `/weekly` 주간 리포트를 제공한다.

이번 범위에 포함되는 기능은 다음과 같다.

- 국제·국내 기사 유형 분류와 표시
- 현재 보관 중인 7일 데이터 백필
- 주간 핵심 동향 3개 산출
- 기사 유형 분포, 전체 주제 순위, 일별 흐름 표시
- 주간 리포트 링크와 메타데이터·사이트맵 반영

카리나 브리핑 분류, 개인 워치리스트, LLM 요약, 기사 유형에 따른 순위 조정, 데이터 보관 기간 연장은 이번 범위에서 제외한다.

## 2. 설계 원칙

1. 무료·무인증·정적 JSON 구조를 유지한다.
2. 분류와 집계는 재현 가능한 결정론적 순수 함수로 구현한다.
3. 객관적 기사 순위는 변경하지 않는다.
4. 기존 저품질 필터를 통과한 기사에만 유형을 부여한다. 분류가 제외 기사를 되살리지 않는다.
5. 기사 유형은 뉴스의 영속 속성으로 저장하고 주간 리포트는 일별 데이터에서 요청 시 파생한다.
6. 주간 리포트 오류가 일일 대시보드에 영향을 주지 않게 경계를 분리한다.

## 3. 기사 유형 분류

### 3.1 타입

```ts
type ArticleType =
  | "news"
  | "analysis"
  | "interview"
  | "review"
  | "pr"
  | "event";
```

표시명은 각각 `보도`, `분석`, `인터뷰`, `리뷰`, `PR`, `행사안내`다.

국제 `NewsItem`과 국내 `DomesticItem`에 `articleType`을 저장한다. 런타임 로더는 백필 이전 데이터의 필드 누락을 `news`로 보정하지만, 새로 저장되는 데이터의 스키마에서는 필수다.

### 3.2 분류 인터페이스

분류기는 다음 값만 입력받는 순수 함수다.

```ts
classifyArticleType({ title, summary, language }): ArticleType
```

- `language`: `ko` 또는 `en`
- 국제 기사는 원문 제목과 번역 전·후 사용 가능한 요약을 사용한다.
- 국내 기사는 한국어 제목과 요약을 사용한다.
- 명확한 신호가 없으면 `news`다.

### 3.3 판정 우선순위

중복 신호가 있을 때 다음 순서를 적용한다.

1. `pr`
2. `event`
3. `interview`
4. `review`
5. `analysis`
6. `news`

강한 제목 패턴을 우선하고 요약은 보조 신호로 사용한다. 단일 인용문만으로 인터뷰를 판정하거나 전시 개최 사실만으로 리뷰를 판정하지 않는다.

주요 신호 예시는 다음과 같다.

| 유형 | 한국어 예시 | 영어 예시 |
|---|---|---|
| PR | 출시, 협업 상품, 공식 발표, 후원 | launches, partnership, sponsored, press release |
| 행사안내 | 신청, 예약, 입장, 운영 시간, 무료 관람 | tickets, registration, opening hours, admission |
| 인터뷰 | 인터뷰, 문답, 작가와의 대화 | interview, Q&A, in conversation |
| 리뷰 | 리뷰, 전시평, 비평 | review, exhibition review, critics' take |
| 분석 | 분석, 전망, 해설, 시장 보고서 | analysis, outlook, report, what it means |
| 보도 | 위 유형의 강한 신호 없음 | no stronger signal |

현재 하드 필터로 제외되는 사진 캡션, 상품성 PR, 기관 관람 안내는 계속 제외된다. 필터를 통과한 경계 사례만 `pr` 또는 `event`로 관찰·표시한다.

## 4. 수집과 데이터 흐름

1. 기존 RSS 수집, 정규화, 필터, 클러스터링과 순위 계산을 그대로 수행한다.
2. 최종 국제 Top 5와 국내 Top 5를 구성한 뒤 각 대표 기사에 유형을 분류한다.
3. `articleType`을 `data/daily/YYYY-MM-DD.json`에 저장한다.
4. 현재 보관 중인 7개 일별 JSON을 동일 분류기로 한 번 백필한다.
5. 순위, 점수, 카테고리, 대표 기사 선택은 유형 분류 때문에 변경하지 않는다.

분류 규칙과 사전은 `scripts/collect.ts` 안에 두지 않고 독립 모듈에 둔다.

## 5. 주간 주제 체계

초기 주제는 다음 8개로 제한한다.

```ts
type WeeklyTopic =
  | "market"
  | "institution"
  | "exhibition"
  | "fair"
  | "artist"
  | "gallery"
  | "restitution"
  | "law-policy";
```

표시명은 다음과 같다.

- 경매·시장
- 미술관·기관
- 전시·회고전
- 아트페어·비엔날레
- 작가·수상·부고
- 갤러리·화랑
- 환수·문화재
- 법률·정책

제목, 요약, 기존 카테고리를 입력받아 주요 주제 하나와 선택적 보조 주제 하나를 반환한다. 한 기사당 최대 두 주제만 인정해 중복 집계를 제한한다. 키워드 신호가 없으면 기존 카테고리를 기반으로 폴백한다.

## 6. 주간 리포트 집계

### 6.1 데이터 범위

- `data/index.json`에 기록된 최근 최대 7일을 사용한다.
- 국제 `top5`와 국내 `domestic.items`를 공통 형태로 정규화한다.
- 카리나 데이터는 제외한다.
- 일부 날짜만 존재하면 확보된 날짜만 집계하고 실제 집계 일수를 표시한다.
- 같은 정규화 URL은 한 번만 집계한다.
- URL이 다르면 정규화 제목과 날짜가 같은 항목을 보조 중복 신호로 사용한다.

### 6.2 주제 점수

주제별로 다음 신호를 합산한다.

```text
동향 점수 =
  관련 기사의 중요도 점수 합
  + 고유 날짜 수 보너스
  + 고유 매체 수 보너스
  + 국제·국내 동시 등장 보너스
```

구체적인 계산식은 다음과 같다.

```text
importance = 주요 주제 기사 score 합 + round(보조 주제 기사 score × 0.5) 합
trendScore = importance
  + uniqueDates × 8
  + uniqueSources × 4
  + (국제·국내 모두 등장하면 12, 아니면 0)
```

- 원래 저장된 기사 점수는 주요 주제에 100%, 보조 주제에 50% 반영한다. 보조 주제가 주요 주제와 같은 비중으로 중복 집계되는 것을 막기 위한 제한이다.
- `uniqueDates`와 `uniqueSources`는 주제에 관련된 전체 기사 집합에서 한 번만 계산한다.
- 고유 매체는 URL의 등록 가능 도메인을 우선 사용하고, URL을 해석하지 못하면 정규화된 `source` 문자열을 사용한다.
- 국제와 국내에 모두 나타난 주제에는 12점을 한 번만 더한다.
- 동점은 `importance → 고유 날짜 → 고유 매체 → 고정 주제 순서`로 판정한다.
- 고정 주제 순서는 §5의 타입 선언 순서와 같다.

상위 3개를 핵심 동향으로 선정한다.

### 6.3 주제 결과

각 주제는 다음 정보를 제공한다.

- 주제와 표시명
- 동향 점수와 중요도 합
- 관련 기사 수
- 고유 날짜 수
- 고유 매체 수
- 국제·국내 출현 여부
- 대표 기사 최대 3건
- 규칙 기반 설명 한 문장

대표 기사는 중요도 점수 내림차순이며 같은 사건의 중복은 제거한다. 설명은 기사 수, 날짜 수, 매체 수, 국제·국내 교차 여부를 조합해 생성한다.

### 6.4 기사 유형 분포와 일별 흐름

기사 유형 분포는 유형마다 다음 값을 집계한다.

- 전체 기사 수
- 국제 기사 수
- 국내 기사 수
- 전체 대비 비율

일별 흐름은 날짜마다 가장 높은 주제와 대표 기사 한 건을 제공한다. 해당 날짜에 기사가 없으면 행을 만들지 않는다.

## 7. 구성요소 경계

### 기사 유형 분류기

- 제목·요약·언어에서 `ArticleType`을 반환한다.
- 수집기, 파일시스템, React에 의존하지 않는다.

### 주간 주제 분류기

- 제목·요약·카테고리에서 주요·보조 주제를 반환한다.
- 한 기사에 최대 두 주제만 반환한다.

### 주간 리포트 집계기

- 여러 날짜의 `DailyData`를 공통 기사로 정규화한다.
- 중복 제거, 점수, 대표 기사, 유형 분포, 일별 흐름을 계산한다.
- React와 파일시스템에 의존하지 않는다.

### 주간 데이터 로더

- 보관 날짜와 일별 파일을 읽는다.
- 개별 파일이 누락되거나 손상되면 해당 날짜만 제외한다.
- 유효한 날짜가 없으면 빈 리포트 결과를 반환한다.

### `/weekly` 페이지

- 집계 결과를 표현만 한다.
- 서버 컴포넌트로 렌더링하고 별도의 클라이언트 상태를 요구하지 않는다.

## 8. 화면 설계

### 8.1 기사 유형 표시

- 국제 이미지 타일은 호버·포커스 오버레이의 메타데이터에 유형 표시명을 추가한다.
- 이미지가 없는 국제 타일은 제목과 함께 작은 유형 배지를 표시한다.
- 국내 목록에는 기존 카테고리 배지 옆에 기사 유형 배지를 항상 표시한다.
- 유형 표시가 링크의 접근 가능한 이름을 대체하지 않는다.

### 8.2 주간 리포트 `/weekly`

1. **주간 개요**
   - 실제 집계 기간과 수집 일수
   - 분석 기사 수
   - 가장 강한 동향
   - 국제·국내 기사 수

2. **핵심 동향 3개**
   - 주제, 동향 점수, 근거 수치
   - 규칙 기반 설명
   - 대표 기사 2~3건

3. **기사 유형 분포**
   - 여섯 유형별 전체·국제·국내 건수
   - 차트 라이브러리 없이 CSS 비율 막대와 숫자로 표현
   - 색상만으로 의미를 전달하지 않는다.

4. **전체 주제 순위**
   - 여덟 주제를 점수순으로 표시
   - 관련 기사 목록은 기본 HTML `details`로 펼친다.

5. **일별 흐름**
   - 날짜, 당일 최상위 주제, 대표 기사 링크

헤더에 `주간 동향` 링크를 추가한다. `/weekly`에는 정적 제목·설명 메타데이터를 적용하고 사이트맵에도 포함한다.

## 9. 실패 처리와 하위 호환성

- 알 수 없는 유형 신호는 `news`로 폴백한다.
- 알 수 없는 주제 신호는 기존 카테고리 기반 주제로 폴백한다.
- 백필 전 데이터의 누락된 `articleType`은 로더에서 `news`로 보정한다.
- 손상된 개별 날짜 파일은 주간 리포트에서 제외한다.
- 대표 기사 수가 부족하면 확보된 기사만 표시한다.
- 유효한 날짜가 없으면 `/weekly`는 오류 대신 빈 상태를 표시한다.
- 주간 집계 실패가 `/`와 `/archive`를 중단시키지 않는다.
- PR·행사안내 유형은 이번 범위에서 점수 감점에 사용하지 않는다.

## 10. 테스트 전략

### 기사 유형 분류

- 한국어·영어의 여섯 유형 대표 사례
- 인터뷰와 일반 인용 보도의 구분
- 리뷰와 전시 개막 보도의 구분
- PR·행사안내 우선순위
- 불명확한 입력의 `news` 폴백
- 현재 보관 기사 회귀 사례

### 주제와 집계

- 주요·보조 주제 최대 두 개 제한
- URL 및 제목 기반 중복 제거
- 고유 날짜·매체 계산
- 국제·국내 동시 등장 보너스
- 결정적인 동점 판정
- 대표 기사 선택
- 유형별 국제·국내 분포
- 일부 날짜 및 빈 입력 처리

### 화면과 통합

- `/weekly` 핵심 섹션 렌더링
- 헤더의 주간 동향 링크
- 국제·국내 기사 유형 표시
- 백필 전 데이터의 `news` 폴백
- 메타데이터, 사이트맵, RSS, 기존 페이지 회귀
- TypeScript, ESLint, Vitest, Next.js 프로덕션 빌드

## 11. 완료 기준

1. 국제·국내 신규 기사에 여섯 유형 중 하나가 저장된다.
2. 현재 보관 중인 7일 데이터가 동일 분류기로 백필된다.
3. 기존 Top 5와 국내 순위가 변경되지 않는다.
4. `/weekly`에서 실제 보관 날짜를 기반으로 핵심 동향 3개를 확인할 수 있다.
5. 주제 점수 근거, 대표 기사, 유형 분포, 전체 주제 순위, 일별 흐름이 표시된다.
6. 개별 국제·국내 기사에서 유형을 확인할 수 있다.
7. 손상되거나 부족한 일부 날짜 때문에 전체 주간 페이지가 실패하지 않는다.
8. 전체 테스트, 타입 검사, 린트, 프로덕션 빌드가 통과한다.
